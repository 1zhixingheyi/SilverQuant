# SilverQuant 架构设计总结

## 项目设计理念

SilverQuant 采用了**分层解耦**和**组件化**的设计理念，旨在为量化交易初学者提供一个**开箱即用**且**易于扩展**的交易框架。

## 核心架构特点

### 1. 分层架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    配置管理层                            │  ← credentials.py、多层存储配置
├─────────────────────────────────────────────────────────┤
│                    AI集成层                              │  ← DeepSeek、Claude、飞书/钉钉通知
├─────────────────────────────────────────────────────────┤
│                    策略执行层                            │  ← 买卖策略、股票池、智能选股
├─────────────────────────────────────────────────────────┤
│                    核心服务层                            │  ← 交易代理、数据订阅、缓存管理
├─────────────────────────────────────────────────────────┤
│                    数据存储层                            │  ← Redis、MySQL、ClickHouse、MinIO
├─────────────────────────────────────────────────────────┤
│                    数据访问层                            │  ← Tushare、AKShare、QMT、MOOTDX
├─────────────────────────────────────────────────────────┤
│                    交易执行层                            │  ← QMT实盘、掘金模拟盘、回测平台
└─────────────────────────────────────────────────────────┘
```

### 2. 关键设计模式

- **策略模式**：不同的交易端实现（QMT、掘金）
- **组合模式**：灵活组合多种卖出策略组件
- **单例模式**：全局股票名称缓存管理
- **装饰器模式**：为函数添加缓存功能
- **观察者模式**：数据订阅和事件回调机制

### 3. 组件化设计

#### 买入组件

- 仓位控制（slot_count、slot_capacity）
- 资金管理（daily_buy_max、once_buy_limit）
- 风险限制（inc_limit、min_price）

#### 卖出组件

- 硬性止损（HardSeller）
- 换仓卖出（SwitchSeller）
- 回落止盈（FallSeller）
- 技术指标（MASeller、CCISeller）

#### 选股组件

- DeepSeek AI选股（DeepSeekSelector）
- 问财智能选股（WencaiSelector）
- 技术指标选股（其他Selector）
- 股票池过滤（StocksPool）

#### AI集成组件

- Claude代码分析（智能代码生成和优化）
- DeepSeek策略生成（AI驱动的选股策略）
- 多模型支持（OpenAI GPT等可选模型）
- 智能通知（飞书/钉钉多平台通知）

## 数据流设计

### 多源数据融合
```
外部数据源 → 数据适配器 → 数据处理 → 缓存管理 → 策略引擎 → 交易执行
```

### 三级缓存策略
- **L1缓存（内存）**：高频访问的基础数据
- **L2缓存（文件）**：历史数据和分析结果
- **L3缓存（远程）**：实时数据和备用源

### 实时处理能力
- Tick级别数据处理
- 事件驱动架构
- 流式数据处理

## 扩展性设计

### 1. 新增交易端
只需实现 `BaseDelegate` 接口：
```python
class NewBrokerDelegate(BaseDelegate):
    def check_asset(self):
        # 实现资产查询
    def order_market_open(self, code, price, volume, remark):
        # 实现市价买入
    # ... 其他接口方法
```

### 2. 新增选股器
继承 `BaseSelector` 并实现选股逻辑：
```python
class MySelector(BaseSelector):
    def select_stocks(self, curr_date, curr_time):
        # 实现自定义选股逻辑
```

### 3. 新增卖出策略
继承 `BaseSeller` 并实现卖出逻辑：
```python
class MySeller(BaseSeller):
    def check_sell(self, code, quote, position, ...):
        # 实现自定义卖出判断
```

## 风险控制设计

### 多层风控机制
1. **硬止损层**：固定比例止损，不可绕过
2. **动态止盈层**：根据市场情况调整
3. **组合风控层**：整体仓位和单票权重控制
4. **监控告警层**：异常情况实时通知

### 资金安全设计
- 交易凭证本地加密存储
- 模拟盘先行测试
- 多重确认机制
- 异常自动熔断

## 性能优化

### 缓存策略
- 数据预加载和懒加载
- 智能缓存更新机制
- 多级缓存降级

### 并发处理
- 多线程数据获取
- 异步消息通知
- 非阻塞交易执行

### 资源管理
- 连接池管理

## 开发指南

### 初学者路径
1. **理解配置**：熟悉 `credentials.py` 和策略参数配置
2. **模拟测试**：使用 `run_wencai_qmt.py` 进行模拟盘测试
3. **参数调优**：根据回测结果调整买卖参数
4. **逐步实盘**：从小资金开始逐步增加仓位

### 进阶开发
1. **自定义选股器**：实现自己的选股逻辑
2. **组合策略**：组合多种卖出组件
3. **风险管理**：开发复杂的风控模型
4. **性能优化**：优化数据处理和交易执行

### 注意事项
- 严格遵守风险控制原则
- 充分测试后再实盘运行
- 定期备份交易数据
- 保持软件版本更新
